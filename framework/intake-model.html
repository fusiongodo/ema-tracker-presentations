Daily intake model

How the app knows what was taken on any given day, with as little logging as possible.

The daily intake is calculated from the version history of each plan. Every plan has a type (ongoing or block) and a rhythm (daily, weekdays or every N days), and any deviations from the plan are logged as events.

One plan, two versions, two deviations

Terms

Plan P-plan

One protocol, e.g. "Epitalon 5 mg every other day". The user's term in the app is plan or protocol.

Type P-type

  • ongoing
  • block
  • as needed

Ongoing has a start date and no planned end. Block has a fixed start and end date and ends by itself; a new block is created manually. As needed (PRN) has no rhythm: it is a preconfigured template, and every intake is logged as an event.

Rhythm P-rhythm

  • daily
  • weekdays
  • every N days

When the plan prescribes an intake. "Weekdays" means selected days of the week; "every N days" counts from the start date.

Version P-version

Every change to a plan creates a new version instead of overwriting the old one. Each version has a valid from date and stays valid until the next version begins. Together the versions form the plan's history.

PreciseValidity is a half-open interval: v1 from day 1 up to but excluding day 5, v2 from day 5. No day ever belongs to two versions.

Calculated intake P-calculated-intake

What the version active on a given day prescribes, according to its rhythm and dose. Computed, never logged.

Deviation P-deviation

  • skip
  • extra

An event the user logs when reality differs from the plan. Only deviations need input, which keeps logging effort minimal.

Actual intake P-actual-intake

Calculated intake plus and minus the logged deviations. This is the value used in analysis.
